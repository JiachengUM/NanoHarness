# 用例编写关键约束（精简版）

这些约束来自 writing.md 的核心要求，必须在生成和审核时严格遵守。

## 🔴 硬性约束（必须遵守，违反即算错误）

### K0. 时间规律发现场景设计原则【新增关键约束】

**核心前提**：时间规律发现的前提是用户在**特定时间**有**重复的具体行为**，助手才能归纳出规律。

**设计 Checklist**（生成/审核时必须检查）：
- [ ] 前三轮用户是否有**明确的具体行为**？（如"空调调到24度"，而非模糊的"调下空调"）
- [ ] 如果没有明确行为，用户之前是否明确建立过偏好？（助手有依据推断该做什么）
- [ ] 第四轮验证时，用户只说"照旧"，助手是否能**主动**执行之前的行为？

**反例**（❌ 严重错误——无厘头场景）：
- 用户说"调下空调"（太模糊，助手不知道该做什么，无法归纳规律）
- 前三轮都是模糊指令，第四轮说"照旧"——根本没有"旧"可循
- 用户从未明确过偏好，助手却"主动"执行了某个操作

**正例**（✅ 正确设计——有具体可归纳的行为）：
```
第1轮："空调调到24度"（明确行为）
第2轮："空调还是24度"（重复行为）
第3轮："和昨天一样"（延续行为）
第4轮："照旧"（验证助手是否主动执行24度）
```

**标签选择原则**：
- 用户意图**明确可直接执行** → **可完成**
- 用户意图**模糊需要追问**（如"调下空调"没说多少度） → **需澄清**
- 用户**多次重复同一具体行为**，验证轮**主动执行** → **时间规律发现**

**重要提醒**：不要为了打「时间规律发现」标签而设计无厘头场景。问自己：
> "一个真实车主真的会在不同日期反复说这种模糊的话吗？助手真的有依据知道该做什么吗？"

如果答案是否定的，这个 case 就不符合乘用车场景常识，必须重新设计。

### K1. 条件变量禁止泄题（§8.3）
- **判题所需的条件变量**（星期、天气预警、车速阈值、时间等）必须只写在 `car_info`/`mock_time`/`日历备注`
- **用户台词禁止复述**这些条件变量
- **反例**（❌ 错误）：用户说"今天早上8点去公司"（mock_time 已是 08:00，用户又说一遍）
- **正例**（✅ 正确）：用户只说"今天去公司"，时间线索在 `mock_time: "2024-01-15 08:00:00"`

### K2. 验证轮禁止复述具体动作（§8.2）
- **时间规律发现/条件规律发现**的末轮（第4轮），用户**不得**复述前几轮已出现的具体车控口令
- **反例**（❌ 错误）：第4轮用户说"关窗/开内循环/调风量"
- **正例**（✅ 正确）：第4轮用户说"照旧""你知道咋办吧"等托付短句

### K3. 断言禁止引用不可见字段（§6.3）
- `nl_assertion` 中**不得**出现 `car_info`、`mock_time`、`mock_info` 等内部字段名
- 应使用**"背景信息"**指代裁判可见的注入信息
- **反例**（❌ 错误）："助手应从 mock_time 中识别早8点规律"
- **正例**（✅ 正确）："助手应从背景信息中的时间线索识别规律"

### K4. car_info 格式规范（§8.6）
- 一行一键值对
- 中文全角冒号分隔：`键：值`（不是 `键:值` 也不是 `键=`）
- 不重复键

### K5. user_query_lists 结构（§9.1）
- **每项 = 一次独立冷启动**，每项内只有**首条** user 消息生效
- 同会话追问写在 `expected_script`，**不要**塞进 `user_query_lists[0]` 的列表
- **反例**（❌ 错误）：`user_query_lists[0].user_query_list` 里有3条 user 消息

### K6. 禁止能力泄题（§8.3b）
- 测「助手主动给替代方案」时，用户**不得**直接说"给我替代方案"
- 测「助手主动归纳规律」时，用户**不得**亲口把规律说出来
- **本质**：你测的是助手"主动"做某事，用户说了就变成测"命令遵循"

### K7. 用户台词中禁止使用占位符（§8.1）
- `user_query_lists`冷启动首条和`expected_script`中`用户：`行是演员照读的台词，**不得出现**`XX`、`某`、`某某`、`待定`、`未知`等占位符
- 地址、地名、店名、路名、小区名、歌曲名等必须写成可真实读出的具体值，TTS 会把"XX路"读成"叉叉路"
- **反例**（❌ 错误）："把我家地址改成XX路123号"、"导航到某某商场"、"播放待定歌曲"
- **正例**（✅ 正确）："把我家地址改成南京西路1266号"、"导航到陆家嘴中心商场"、"播放周杰伦的晴天"
- 如果确实需要表达"任意地址"，应把具体值写进`car_info`，让用户句引用`car_info`中的信息，而不是在用户句里写占位符

### K8. context_config 只应包含场景上下文（§10.1b）
- `context_config` **只应包含** `car_info` 等场景上下文，禁止生成任何与 agent 部署、后端存储、记忆库相关的配置字段
- 用例测记忆类能力时，只需通过用户台词和 `car_info` 描述场景，系统侧记忆由测试环境统一注入
- **反例**（❌ 错误）：`context_config` 中出现除 `car_info` 以外的配置字段
- **正例**（✅ 正确）：`context_config: { car_info: "..." }`

### K9. 对话形式标签必须与 `user_query_lists` 结构一致（§9.3）
- `单轮对话` → `user_query_lists` 只有 1 个 session，`expected_script` 中无后续 `用户：`行
- `多轮对话`（含 `多轮对话_2到3轮` 等）→ `user_query_lists` 只有 1 个 session，后续轮次写在 `expected_script` 的 `用户：`行
- `多次多轮`（含 `多次多轮_2次会话` 等）→ `user_query_lists` 有多个 session，数量与标签对应
- `追问连续回答` 必须同时打 `多轮对话` 对应轮数标签，且为单 session
- **反例**（❌ 错误）：打了 `追问连续回答` 但 `user_query_lists` 有 2 个 session，或没打 `多轮对话` 标签
- **正例**（✅ 正确）：`追问连续回答` + `多轮对话_2到3轮`，`user_query_lists` 1 个 session，追问写在 `expected_script`

## 🟡 软性约束（应遵守，视情况可适度调整）

### S1. 用户台词口语化
- 像真人车主短句吩咐，一两句说完
- **禁止**考题腔："高风险口径""类型识别清楚""对比两条ETA"
- 这些判定点放在 `nl_assertion`/`管家：（…）`

### S2. 标签区分（§2.1b）
- `温度增减调节` vs `温度直接设定`："调低2度"→增减；"调到26度"→直接
- `精确地点直达` vs `结果可直接导航`：用户给明确地址→直达；用户说"万达"从结果选→可导航

### S3. 记忆类必须「生产→消费」闭环（§10.1）
- **禁止**单条超长用户句完成「建立+推翻+再决策」
- 必须：**多段 user_query_lists**（多冷启动）
- 前几项生产记忆，最后一项消费验证

### S3a. 生产轮必须真实执行（§10.1a）
- 生产轮若用户请求了执行（如"现在放一下"），助手**必须先执行再记录**
- **禁止**管家块只写"记录偏好"而无执行反馈——会导致消费轮指代悬空
- **反例**（❌ 错误）：用户说"现在放一下"，管家只回复"我会记录您的偏好"
- **正例**（✅ 正确）：管家先写"已为您播放周杰伦的《晴天》"，再沉淀记忆

### S3b. 记忆来源是系统侧沉淀，禁止用户口述冒充（§10.1b）
- 跨会话记忆是**系统在之前真实交互中存的**，不是用户当前会话里嘴说的"我上周听了XX"
- **禁止**用用户口述历史冒充记忆来源
- **反例**（❌ 错误）：用户说"我上周听了周杰伦"→助手据此播放（这是基于陈述的点播，不是记忆调用）
- **正例**（✅ 正确）：通过 context_config 注入系统侧记忆，用户直接说"放上周听的"

### S3c. 消费轮指代必须指向生产轮已真实完成的对象（§10.1c）
- 消费轮的"那首""照旧""就放那个"必须能在生产轮找到**已真实完成的执行结果**
- **禁止**生产轮没放成功，消费轮却指望"放那首"——无源可指，闭环断裂

### S3d. 状态依赖型指令必须先建立前置状态（§14b）
- 状态依赖型指令（暂停/下一首/上一首/切歌/导航取消/导航改线/导航状态询问等）操作的是"当前状态"
- 用例必须**先建立前置状态**（先播放某首歌、先发起导航），再下达状态依赖指令
- **禁止**用例里从未播放过任何歌曲，用户却直接说"暂停当前音乐"——评测不可复现
- **反例**（❌ 错误）：`user_query_lists: [["暂停当前音乐"]]`——助手面对的播放状态未知
- **正例**（✅ 正确）：第一冷启动"播放周杰伦的《晴天》"→第二冷启动"暂停"——有明确操作对象

### S4. max_round 裕量（§14）
- 规律类：14-18（留裕量）
- 简单单轮：5-8
