# MVMS介绍（5%）

MVMS表示Minimal Viable Meory System, 意为“**最小可行记忆系统**”。它模仿了Minimum Viable Product（最小可行产品）这个概念。

它表示最核心的记忆系统的实现。目标不是完美无缺，而是用最小的成本、最快的速度开发并验证**重要不确定问题的解法的可行性**，用于指导真实产品的迭代和开发。

这个文档只写基本的框架和思路。具体的细节需要参见代码和数据库的说明。

# 它为何存在（why）

一个好的记忆系统需要考虑很多因素，包括测试数据，测试框架，memory的数据库设计，工程架构设计等。

我们在几乎所有方面都缺乏积累和认知。如果直接在产品工程的环境下开发和测试，会因为其巨大的不确定性造成开发的低效，甚至来回返工。

为此，这里是一个试验场，供开发者快速执行“设计 -> 开发 -> 测试”的闭环。待测试基本过关，代码架构基本稳定后，再迁入到产品中进行最终的测试和发布。

简单说，**这里做预研，回答所有重要不确定问题**。


重要不确定问题包括但显然不限于（需要迭代和补充）

- 用户画像
- memory类型定义，典型示例（边界在哪里）
- 产品场景的详细定义，典型示例（边界在哪里）
- 重要测试的初步结论
- 数据结构的设计
- Agent框架，API设计
- 底层数据库的选型和设计

# 它如何开发（how）

MVMS本质上就是代码仓库和数据库，因此，可以做版本控制，溯源和归因。

它和nanoai包的定位不同，要求和开发过程也不同。

- **nanoai包**：目的是产品直接可用（目前还达不到，但定位如此）。质量需要足够高: 稳定性，可扩展性，鲁棒性，性能等。

- **MVMS包**：目的是预研，获得关键认知。大量内容都是实验性质，不需要稳定，迭代要快。稳定的内容进入nanoai。

注意事项

- 会有很多零零碎碎的内容，无需太注重格式。按照自己的理解写单个module，组织各种module即可，**快速开发，快速测，快速获得认识最重要**。先污染再治理。待乱到一定程度后， weiyichen会统一整理。
- 这里只包括“如何开发”的规范和思想。具体的开发过程细节管理在[飞书文档](https://pq3b44yw2t9.feishu.cn/wiki/PDFew4A6cibUawkHlshcJTJfn5e#share-XchydzL6AobgW0x9Hv4cvQFznxh)。
