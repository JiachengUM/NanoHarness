# 项目审核原则覆盖

本节记录本项目对基础审核原则（`skills/_shared_case_audit_principles.md`）的覆盖和增补。审核时发现了项目特有的问题，就补什么。**本项目审核原则优先于基础审核原则**，两者冲突时以本文件为准。

本项目暂无覆盖。以下为模板和示例，实际使用时删除。

## 覆盖模板

```markdown
### <被覆盖的基础审核原则章节>
**什么变了**：基础审核原则里说……，本项目因 <原因>，调整为……
**影响**：审核时……
**示例**：
  原则判定：……
  调整后判定：……
```

## 新增审核要点模板

项目标签树中独有的叶子或项目特有的审核场景，在此补充审核要点：

```markdown
### <新增审核要点名>
适用标签：...
触发条件：...
审核要点：
  用户台词：...
  断言审查：...
  标签审查：...
  边界：与通用XX原则的区别...
```

## 冲突检查清单

每个新增审核要点或覆盖项，逐项回答即可。回答"是"意味着需要在本文件补充说明。

| 检查项 | 回答"是"意味着什么 |
|--------|-------------------|
| 项目有特殊的安全合规要求？ | 须写明哪些请求应拒绝/降级，与通用B3/B6是否冲突 |
| 项目的感知能力与默认不同？ | 须写明助手能感知什么信息，与E2是否冲突 |
| 项目有特殊的记忆策略？ | 须写明记忆生产/消费规则，与A4/A5/C2是否冲突 |
| 项目的标签树有独有叶子？ | 须补充该叶子的审核要点，与D2粒度区分是否需要新增 |
| 项目的用户画像与通用不同？ | 须写明用户台词风格，与A1/A2是否冲突 |
| 项目有特殊的交互闭环要求？ | 须写明expected_script格式，与F3是否冲突 |
| 项目的断言标准与通用不同？ | 须写明断言写法，与B1-B3b是否冲突 |
