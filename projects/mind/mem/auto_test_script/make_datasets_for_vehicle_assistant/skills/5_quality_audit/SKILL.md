# Dataset Quality Audit

质量审计环节。检查用例质量问题，输出审计报告。

> **用例编写通用原则**：本环节与环节2、4共享用例编写/审查原则，详见 [_shared_case_writing_principles.md](../_shared_case_writing_principles.md)。审计时以该共享原则为判定标准。**项目写作原则优先于基础原则**，两者冲突时以项目增补为准。
>
> **用例审核通用原则**：审计 Prompt 中的审核原则来自 [_shared_case_audit_principles.md](../_shared_case_audit_principles.md)，项目级审核原则覆盖见 `<P>/tag_tree/case_audit_supplements.md`（优先级更高，冲突时以项目级为准）。`full_case_audit.py` 运行时自动加载并合并两者。

**公共服务**：本环节被两个生产循环共用——叶子用例生产循环（环节2→5→6）和复合用例生产循环（环节4→5→6）。每写完一批用例，就调用本环节审计。

## 输入

| 产物 | 目录 | 说明 |
|------|------|------|
| 用例主库 | `<P>/cases/vehicle_assistant_cases.json` | 待审计的主库 |
| 项目标签树 | `<P>/tag_tree/vehicle_assistant_case_tag_tree.json` | 叶子标签全集（用于标签审计） |
| 项目打标指南 | `<P>/tag_tree/vehicle_assistant_case_tagging_guideline.md` | 标签语义定义+项目写作原则覆盖（用于标签粒度审计，优先于基础原则） |

## 输出

| 产物 | 目录 | 说明 |
|------|------|------|
| 审计报告 | `<P>/audit_results/` | 审计结果详情（问题清单，每条case的问题分类+具体描述） |

**本环节只输出问题，不修复用例。** 修复在环节6进行。

## 审计维度

### A. 用户台词审计

| 检查项 | 说明 |
|--------|------|
| 记忆泄题 | 测不自动记录时车主说了「记住」/「别记」 |
| 能力泄题 | 测主动给替代时车主说了「给我替代方案」 |
| 条件变量泄题 | 车主口述了应放 `car_info` 的条件变量 |
| 考题腔 | 车主像在念评测任务书 |
| 悬空指代 | 冷启动首条含无上文指代（「这款」「那人」） |
| 跨冷启动承接 | 第二冷启动出现「附上」「接着刚才」 |

### B. 断言审计

| 检查项 | 说明 |
|--------|------|
| 废话断言 | 只有通用断言、无 case 专属断言 |
| 禁止类断言缺"不得" | 断言意图是禁止助手做某事，但写成了正向陈述（如"生成对立文案"），等于要求助手作恶，必须加"不得"开头 |
| 引用后台操作 | 写「通过车控工具调用」「须调用联网检索」（导演看不见） |
| 违法请求要求替代 | 违法请求没有合法替代方案，断言只须要求拒绝 |
| 断言冗余重复 | 多条断言判定结果完全一致 |

### C. 结构审计

| 检查项 | 说明 |
|--------|------|
| `user_query_lists` 同sess堆多条 | 冷启动只认首条，第2轮起应只在 `expected_script` |
| 记忆题单句自打自脸 | 同一条 `user_query_list` 里一次说完记忆建立与推翻 |
| 不记录却单会话 | 无法验证检索侧是否伪调用记忆 |
| 对话轮次标签与实际不符 | expected_script 多轮但 tags 标单轮 |

### D. 标签审计

| 检查项 | 说明 |
|--------|------|
| 非叶子标签 | tags 含中间节点名 |
| 互斥结果标签共存 | `可完成` + `需澄清` 等 |
| 标签覆盖不完整 | 多个操作只标了其中一个 |
| 联网标签误打 | POI 检索、导航、记忆类 case 不涉及联网信息查询，却误打了联网叶子标签 |
| 标签粒度混淆 | `温度增减调节` vs `温度直接设定` 等 |

### E. 场景审计

| 检查项 | 说明 |
|--------|------|
| 座舱错位 | 办税窗口、写字楼等非车内主场 |
| 场景—角色—座位不一致 | 代驾+副驾车控矛盾 |
| 伪视觉/伪雷达 | 期望助手看图像但未注入结构化摘要 |

### F. 格式审计（程序化、确定性）

| 检查项 | 说明 |
|--------|------|
| expected_script 格式不统一 | `【自动评测说明】`、`管家：台词`（非括号）等 |
| 用户句含导演尾巴 | `（概括）`、`（口述即可）`、`（模糊指代）`等 |
| 工程字段名未替换 | `car_info`、`mock_info`、`mock_time` 等出现在裁判可见文本中 |
| Schema 不合法 | case 结构不符合 Case Schema 定义 |

## 审计管线

### 第一层：规则审计（快速、确定性）

1. **格式问题扫描**：`scripts/normalize/` 下各脚本（dry-run 模式）
   - 归一化扫描、尾巴扫描、工程用语扫描、Schema 校验

### 第二层：LLM 语义审查（深度、概率性）

2. **全量六维度审计**：`scripts/audit/full_case_audit.py`
   - A-F 六大类原则完整 Prompt（从 `_shared_case_audit_principles.md` + `case_audit_supplements.md` 加载）
   - 调用 LLM 并发审查

## 迭代模式

### 自回溯

- 审计是只读操作，不修改用例数据
- 修复用例后重跑审计验证（环节6的循环）
- 人类可先看审计报告，决定哪些问题需要修复

### 跨环节回溯

| 触发场景 | 回溯方式 |
|---------|---------|
| 审计发现标签错误（非叶子、互斥共存等） | 回到环节1/2修正标签树和用例标签 |
| 审计发现用例对话不自然/断言不准确 | 回到环节2/4修复特定用例 |
| 审计发现场景错位（座舱错位等） | 回到环节4重写该用例 |

## 完成标准

- 规则审计 0 issue
- LLM 审计通过率 ≥ 95%
- 内容合规专项 0 issue
- 无非叶子标签
- 无互斥结果标签共存

## 脚本

| 脚本 | 用途 |

| `scripts/audit/batch_audit_fix.py` | 批量审计+修复循环 |
