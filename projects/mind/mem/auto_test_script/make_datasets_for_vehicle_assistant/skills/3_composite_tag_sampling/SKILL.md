# Composite Tag Sampling

复合标签组合采样环节。

## 核心问题

叶子标签的组合空间是天文数字，无法穷举。而且标签不平等（`单轮对话`几乎每条case都有，`多遮阳帘控制`只有极少数case涉及），不能简单做两两覆盖。有些标签天然不应共现，但这需要场景常识判断，无法用简单规则穷举。

**本质**：靠对车载助手场景极深的理解和想象力，尽量想出各种说得过去的车载场景，为每个场景总结出其对应的标签组合。

## 方法论：场景驱动，而非标签驱动

```
自底向上（标签→组合→场景）  ← 不可行，组合爆炸+互斥约束难编码
自顶向下（场景→标签→覆盖）  ← 可行，场景是天然的多标签载体
```

真实车主不会为了覆盖标签组合而说话，他们是在某个场景下自然地触发多个能力。所以应该**先想场景，再标注标签**。

### 第一步：枚举典型车载场景

基于车载助手领域常识，枚举车主真实会遇到的场景。每个场景天然涉及多个标签。

**场景枚举原则**：
- 按类别枚举：单域复合→跨域联动→理解挑战→鲁棒性→结构复杂，逐类扫描
- 高频场景优先：通勤、导航、音乐、空调是车主每天都会用的
- 低频场景不遗漏：遮阳帘、冰箱、后视镜等也要有场景覆盖
- 边界场景重点覆盖：记忆冲突、合规拒绝、降级处理等是质量分水岭
- 跨域场景是核心价值：单域case在叶子示范中已有，复合case的价值在于跨域
- 理解挑战是高频痛点：车控+理解(153条)、导航+理解(98条)是数据集中最大的跨域模式

### 第二步：为每个场景标注标签

对每个场景，标注自然涉及的叶子标签。标注原则：
- 只标注该场景**自然触发**的标签，不为凑标签硬加
- 互斥结果标签只选其一（`可完成`/`需澄清`/`应拒绝`/`应降级处理`）
- 记忆类场景必须包含生产+消费闭环
- 结构标签（多轮/跨会话）根据场景复杂度自然标注

### 第三步：覆盖缺口分析

将场景模板的标签集与已有case的标签集对比：
- 哪些场景模板还没有case覆盖
- 哪些场景模板有case但标签覆盖不完整
- 哪些叶子标签从未出现在任何场景模板中

### 第四步：饱和度判断

无法穷举，但可以衡量做到什么程度了：

| 指标 | 衡量什么 | 方法 |
|------|---------|------|
| 场景模板覆盖率 | 已覆盖的场景模板数/总场景模板数 | 每轮统计 |
| 高频场景覆盖 | 通勤/导航/音乐/空调等核心场景是否都有 | 必须全部覆盖 |
| 低频场景有代表性 | 遮阳帘/冰箱等低频场景至少有1-2条 | 逐项检查 |
| 饱和曲线 | 新增场景模板的边际收益 | 画曲线，趋于平坦时接近饱和 |
| 缺口清单 | 从未被任何场景模板涉及的叶子 | 定向补全 |

### 第五步：常识过滤

用场景常识判断标签共现的合理性：
- **硬约束**（可编码）：互斥结果标签不共存、记忆消费必须有生产
- **软约束**（需推理）：两个标签是否可能在同一车载场景自然共现，由领域常识判断

## 迭代模式

场景模板是持续演进的产物，每次运行应基于当前状态增量补充。

### 自回溯

本环节的输出（场景模板 + 覆盖缺口报告）可作为下次运行的输入：
- 如果 `scenario_templates.json` 已存在，读取已有场景模板，只补充缺口
- 人类可直接编辑场景模板（修改标签组合、新增场景等），下次运行时保留
- 增量模式：只生成未被已有场景模板覆盖的新场景
- 全量模式：用户明确要求时，从零重新枚举所有场景

### 跨环节回溯

| 触发场景 | 回溯方式 |
|---------|---------|
| 环节1标签树变更（新增叶子） | 回到环节3补充涉及新叶子的场景模板 |
| 环节7发现覆盖缺口 | 回到环节3针对缺口叶子补充场景模板 |

### 人类编辑保留

- 人类手动新增/修改场景模板后，在该条中添加 `"manually_edited": true` 字段
- 运行时跳过带该标记的场景模板，不覆盖人类修改
- 覆盖缺口分析仍会统计手动添加的场景模板

### 迭代记录

在 `scenario_templates.json` 根节点记录：
```json
{
  "iteration": 2,
  "last_updated": "2026-05-28",
  "total_scenarios": 55,
  "new_this_round": 5
}
```

## 产出格式

`scenario_templates.json` 中每条包含：

```json
{
  "scenario_id": "scenario-001",
  "scenario_name": "日常通勤-空调音乐导航",
  "description": "车主上班途中，先调空调温度，再让助手播放喜欢的歌手，最后导航去公司",
  "tags": ["温度增减调节", "按歌手点播", "精确地点直达", "常用地点记忆", "多轮对话_2到3轮"]
}
```

`coverage_gap_report.json` 包含：

```json
{
  "total_scenarios": 50,
  "covered_scenarios": 35,
  "uncovered_scenarios": ["scenario-012", "scenario-023", ...],
  "never_appeared_leaves": ["多遮阳帘控制", "冰箱模式切换", ...],
  "saturation_score": 0.7
}
```
