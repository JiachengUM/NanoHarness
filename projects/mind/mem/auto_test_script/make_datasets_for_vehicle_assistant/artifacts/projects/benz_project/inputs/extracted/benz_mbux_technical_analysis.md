# 奔驰 MBUX 助手技术方案揣摩与能力边界分析

> 本文档基于 `benz_mbux_assistant_prd.md` 反向推导的系统提示词，进一步揣摩其技术实现方案、架构设计、能力边界与薄弱环节，为后续测试用例生成提供"攻击面"指引。

文档版本：v1.0
分析对象：奔驰 MBUX 主动式数字座舱助手（线上 Agent）

---

## 1. 架构推断

### 1.1 整体架构：提示词驱动的单轮 JSON 输出 Agent

从 PRD 反推，助手是**单轮 JSON 输出 + 工具调用（tool_call）+ 状态注入**的 Agent 架构，而非多轮 ReAct 或 Chain-of-Thought 架构。

**关键证据**：
- §4 输出协议：每轮输出一个紧凑 JSON，含 `talk` + `task_list`，没有 `thought` / `reasoning` 字段
- §5.1 stage 判定：助手每轮先自判 stage，再按 stage+领域查表定位话术——这是**规则查表**而非自由推理
- §15.7 "禁深度思考进 talk"：明确禁止推理旁白，说明思考过程要么不发生，要么在模型内部完成不输出
- §6.3 "工具规范：只用定义好的工具，禁编造"——工具集是封闭枚举

**推断架构**：
```
用户输入
  ↓
[系统提示词 + 动态上下文注入]
  - vehicle_state（车辆实时态）
  - reference_context（近期反馈）
  - user_memory（画像）
  - tool_feedback（上轮工具结果）
  ↓
[LLM 单轮推理 → JSON 输出]
  {talk, task_list, dialect?, tone?, reject?}
  ↓
[工具执行层] → tool_feedback → 注入下一轮
```

### 1.2 状态管理：外部注入而非对话历史维护

助手**不维护对话历史状态**，所有状态由外部每轮注入：
- `vehicle_state`：当前播放、导航态、位置、家公司地址
- `reference_context`：近期导航/搜索/播放记录、tool_feedback
- `user_memory`：用户画像（偏好、联系人、日程）
- `tool_feedback`：上轮工具执行结果

**关键推断**：助手看到的对话历史是**平台裁剪后注入的**，不是原始完整历史。这意味着：
- 助手对"三轮前说过什么"的记忆依赖 `reference_context` 的保留策略
- §19.2 明确"历史 assistant 暂无记录/请先登录类旧答过期无效"——平台会主动清除某些旧答
- 助手无法主动查询完整对话历史，只能消费注入的片段

### 1.3 工具集：10个工具，封闭枚举

| 工具 | 作用 | 关键约束 |
|---|---|---|
| `car_control` | 车控 | 判界三分法，白名单封闭 |
| `navigate` | 导航执行 | 定清才导，禁裸名直导 |
| `poi_search` | POI搜索 | 与 info_search 二选一禁混用 |
| `music_playback_control` | 音乐 | 源锁死QQ音乐（除非指定） |
| `radio_playback_control` | 电台广播 | 不支持搜台/收藏/查当前 |
| `tuner_playback_control` | 调频收音 | 支持搜台/收藏/查当前 |
| `audiobook_playback_control` | 有声书 | 模糊需求须先 info_search |
| `movie_search` | 爱奇艺片源检索 | 指纹门禁，续集视为不同作品 |
| `movie_playback` | 爱奇艺正片点播 | 须先 movie_search |
| `video_playback_control` | 视频播控/非爱奇艺 | 不走 movie_search |
| `info_search` | 通用联网搜索 | 实时信息强制下发 |
| `task_master` | 提醒 | 间隔<1分钟拒答 |
| `memory` | 通用记忆 | 敏感内容禁写，每轮重判权限 |
| `personal_place_memory` | 家/公司地址 | 不提供查询 |
| `vehicle_manual` | 车书查询 | 不用常识替代官方答案 |

## 2. 能力边界深度分析

### 2.1 车控域能力边界

#### 2.1.1 判界三分法（核心逻辑）
```
用户车控指令
  ↓
能否映射到白名单域？
  ├─ 否 → A类拒答"这辆车还没有这个功能。"
  └─ 是 → 动作/参数是否明确？
      ├─ 明确且支持 → Act（下发 task_list）
      ├─ 明确但不支持 → B类拒答"当前不支持语音控制{项}。"
      └─ 不明确 → Clarify"{实体}想怎么调？"（task_list=[]）
```

#### 2.1.2 不支持清单（featurelist_config_exclusions）——攻击面
| 域 | 不支持项 | 拒答类型 |
|---|---|---|
| 空调 | 节能/强劲模式、驻车空调 | B类 |
| 香氛 | **类型切换** | B类 |
| 座椅 | **按摩及档位/模式**、**前后/高度/靠背调节** | B类 |
| 影像 | 360全景 | B类 |
| 后视镜 | **展开/折叠/角度调节**（仅支持加热） | B类 |
| 雨刮 | **开关/自动/模式** | B类 |
| 驾驶 | 悬架阻尼、能量回收、关闭无线充电 | B类 |
| 门锁 | **整类不支持**（中控锁/儿童锁/近车解锁等） | B类 |
| 后备箱 | **语音开关** | B类 |
| 胎压 | 预警开关、复位 | B类 |
| 声场 | **全车/前排/后排**模式 | B类 |
| 电台 | 按频率/区域/类型/名称搜台（仅 tuner 支持） | B类 |

#### 2.1.3 隐喻映射陷阱（高频出错点）
- **情境氛围 ≠ 灯效模式**："动感/浪漫/柔和"不得映射为氛围灯模式
- **身体冷热映射**：脚冷→空调暖风吹脚，但背/腰/颈/头/肩不得推断为风向
- **后背热**：不得推导"吹后背"，须走座椅通风或空调降温
- **部位不适无热**：背/腰/颈酸→座椅加热/通风，不得发明风向
- **隐喻拒答**：雨水/刮一下→雨刮（B拒）；腰酸/按一下→按摩（B拒）

#### 2.1.4 param格式红线（易错点）
- **单一性**：每条 param 仅含单一位置+单一动作+单一实体
- **禁合并**：多位置须同轮并行多个 tool_call
- **泛称灯光强制拆分**："调暗灯光"→须拆为4条（氛围灯+阅读灯+内部照明+内灯）
- **别名转换**：自动泊车→打开APA；NOA/导航辅助→打开NOA

### 2.2 导航域能力边界

#### 2.2.1 定址链（核心流程）
```
待定点 → 选择器优先级 → 唯一可定址 → navigate
  ↑                    ↑
  锚点判定              禁裸名直导
```

**选择器优先级**：
1. vehicle_state（当前位置/家公司/原路线）
2. reference_context（"那/那里/上次去的"）
3. 画像→memory(read)（关系人地址）
4. poi_search / info_search（二选一禁混用）

#### 2.2.2 不支持边界
- **途经点增量 patch**：必须整段重导航
- **未定址POI直导**：必须先定清
- **餐厅/商铺专名裸名直导**：必须先 poi_search
- **境外目的地**
- **未导航时独立查前方路况**
- **迷路/找不到路**：须先问当前位置，禁直接导航

#### 2.2.3 多段出行易错点
- **禁多个站点候选一次全列出**：每轮只展示一个站点的候选
- **多复场景**：首轮只定一站→逐站定→全部定清后一次性 navigate
- **task_list 未定清不导**：禁中途 navigate

### 2.3 媒体域能力边界

#### 2.3.1 音乐播放红线
- **源锁死**：未指定APP→默认QQ音乐；禁根据 vehicle_state 改写源
- **禁仅memory替代收藏**：用户说"收藏"必须调 playback_control
- **复杂描述找歌**：必须先 info_search 定名，禁臆选歌名直调
- **曲目溯源**：直接读 vehicle_state 直答，禁 info_search / memory
- **预约限制**：仅支持预约下一首，不接预约第N首之后

#### 2.3.2 影视域指纹门禁（高频出错点）
- **续集/重制/大电影视为不同作品**：须询问且 task_list=[]
- **锁定指纹防篡改**：锁定后只能补细节，禁更换目标
- **禁同轮混用** movie_playback + video_playback_control
- **禁推荐列表多部同轮下发多个播放 task**

#### 2.3.3 电台 vs 调频路由陷阱
- `radio_playback_control`：泛播/播控/APP开关，**不支持搜台/收藏/查当前**
- `tuner_playback_control`：泛播/搜台/播控/收藏/APP/查当前
- **搜台强制改路由**：含地区/频率/台名/频道名→必须走 tuner

### 2.4 提醒域能力边界

#### 2.4.1 禁创建类型
- 动态间隔 < 1 分钟（每隔N秒）
- 一次性相对 < 1 分钟/秒级（30秒后）
- 口语备忘（"记得…/别忘了…"无"提醒我/设提醒/定闹钟"、无准确时间）→ 只聊天
- **条件/场景锚点无准确时间**（到目的地后/到公司后/停车后/下车前）→ 澄清，禁创建
- 模糊时间（等下/过会儿/有空的时候）→ 澄清
- 一次性 > 365 天 → 拒答
- **条件触发车控**（当空调…后）→ 不支持
- 禁 car_control 替代定时；禁 memory 管理提醒

#### 2.4.2 任务id处理（易错点）
- 有id时 param 必带 `(id: xxx)`
- 同名多条禁仅靠任务名/相对时间猜测
- id 只进 param，不进 talk

### 2.5 记忆域能力边界

#### 2.5.1 每轮重判权限
- 必须先看本轮 `user_memory` 的"记忆执行权限"和"执行建议"
- 拒绝→直接输出建议结束；准许→正常使用
- 禁延续历史拦截结论

#### 2.5.2 防串约束
- **可信源**：user_memory、memory(read) feedback、本会话用户亲口陈述
- **不可信源**：reference_context、历史对话、他人表述、vehicle_state 当前播放（禁当长期偏好）
- 禁把 reference_context 当长期偏好写入 memory

#### 2.5.3 歧义无法唯一判定对象时禁create
- "好听/喜欢这首"：歌曲重心优先，取歌名不取歌手
- "少推荐这个"：结合上下文不能唯一判定→task_list=[] 澄清

### 2.6 话术风格红线（易触发违规）

#### 2.6.1 禁句清单
> 这是我该做的 / 很高兴帮您 / 客气啥 / 要不要放歌 / 为您服务 / 不太了解 / 我去看看 / 希望对您有帮助 / 哎哟

#### 2.6.2 禁单一回应词
> 好/好的/行/可以/明白/知道/收到/没问题/了解/ok/OK/嗯（多指令固定句除外）

#### 2.6.3 禁萌系尾缀
> 宝宝/亲/哦/呀/呢/哇/哈哈/天呐/太棒了

#### 2.6.4 首轮承接句限制
- 必说，一句简短自然（5字以内）
- 禁复述用户目标、实体名、查询内容
- 多指令时固定"收到您的指令，准备执行。"

#### 2.6.5 执行中静默
- `talk=""`：内部工具衔接、检索定名、下发播放等中间轮均静默

## 3. 薄弱环节与技术债务推断

### 3.1 stage判定依赖规则查表 → 边界模糊处易错

PRD §5.1 的 stage 判定（首轮/反馈处理/成功/失败/执行中）是规则查表，当工具feedback语义模糊时（如"操作已提交但结果未知"），stage 判定易出错，导致话术策略选错。

### 3.2 定址链多分支 → 分支选择易错

导航定址链有4级选择器优先级，每级又有子规则。当用户说"去上次和老张去的那家烤肉店"时，需同时处理 reference_context + memory(read) + poi_search 三级，分支选择极易出错。

### 3.3 隐喻映射规则复杂 → 语义边界处易错

身体冷热映射有6条规则，情境氛围 vs 灯效模式有3条规则，这些规则在语义边界处（如"我有点冷"无位置修饰、"背上不舒服"非典型酸痛）极易误判。

### 3.4 媒体域路由复杂 → 跨域混用易错

- 音乐 vs 影视：综艺曲目走 playback_control 不走 movie
- 电台 vs 调频：搜台走 tuner 不走 radio
- 爱奇艺 vs 非爱奇艺：正片点播路由完全不同
- 复杂描述找歌：必须先 info_search，禁臆选

### 3.5 记忆防串约束 → 上下文污染易错

reference_context 的短期记录禁当长期偏好写入，但语义边界模糊时（如"这首歌不错"是短期情绪还是长期偏好）易误判。每轮重判权限若延续历史结论则违规。

### 3.6 多指令并发与阻塞排队 → 优先级与排队逻辑易错

优先级：车控 > 音乐/影视 > 导航。阻塞排队时"仅先处理阻塞项，其余排队"。当3个意图中1个需澄清时，需准确判断哪个阻塞、哪些排队，且后续轮次要记得推进排队的任务。

### 3.7 失败禁重试 → 失败后处理易错

8个工具失败禁重试，但"禁重试"指禁同参数重试，还是禁任何形式再调用？若用户换个说法重新请求，是否算重试？边界模糊。

### 3.8 方言/语气跨轮保持 → 状态维持易错

§20.10 tone/dialect 跨轮保持，但助手不维护对话历史，方言/语气状态如何跨轮保持？依赖外部注入还是每轮重新判定？边界模糊。

## 4. 关键依赖与脆弱点

### 4.1 强依赖 vehicle_state 注入

家公司地址、当前位置、当前播放内容等**强依赖 vehicle_state 注入**。若 vehicle_state 缺失或过期：
- "回家"→无法导航（§9.4 家公司仅从 vehicle_state 取，禁 memory 补全）
- "这首歌谁唱的"→无法直答（须 vehicle_state 当前播放）

### 4.2 强依赖 reference_context 指代消解

"那/那里/上次去的"**强依赖 reference_context**。若 reference_context 被裁剪或丢失：
- "导航到上次去的烤肉店"→无法消解"上次去的"
- 须额外澄清或重搜

### 4.3 强依赖 tool_feedback 状态流转

stage 判定、任务id提取、定清确认**强依赖 tool_feedback**。若 feedback 格式异常或语义模糊：
- stage 误判 → 话术选错
- 任务id丢失 → 无法取消/修改
- 定清失败 → 禁导航

### 4.4 强依赖 user_memory 权限注入

记忆操作**每轮强依赖 user_memory 权限注入**。若权限注入延迟或缺失：
- 权限不明 → 记忆操作可能误拒或误准

## 5. 推断的技术局限

### 5.1 无多轮推理能力

单轮 JSON 输出架构意味着：
- 无法处理需要多步推理的复杂任务（如"先查航班，再根据到达时间设提醒，然后导航去机场"）
- 复杂任务须拆解为多个单轮，依赖外部状态注入维持上下文

### 5.2 无主动澄清能力

Clarify 只能问一个阻塞问题，无法主动提供选项或建议。用户回答后才能继续，交互效率低。

### 5.3 无工具组合编排能力

工具调用是扁平的 task_list，无法定义工具间的依赖关系或条件分支。复杂链路（如 movie_search→movie_playback）须靠提示词硬编码规则保证串行。

### 5.4 无错误恢复能力

失败禁重试意味着工具失败后只能告知用户，无法自动降级或换策略（poi_search=0家时强制降级 info_search 是少数例外）。

### 5.5 无长程记忆能力

依赖外部注入的 reference_context 和 user_memory，助手自身无法回忆完整对话历史。长程任务（如跨多轮的旅行规划）易丢失上下文。

---

## 6. 总结：能力边界一句话

**奔驰MBUX助手是一个提示词驱动的单轮JSON输出Agent，强项是封闭域内的高效执行（车控/导航/媒体/提醒），弱项是复杂推理、长程记忆、隐喻边界判断、跨域路由、多指令并发排队。其能力边界由10个工具的白名单/不支持清单严格界定，边界处的语义模糊地带是测试用例的最佳攻击面。**
