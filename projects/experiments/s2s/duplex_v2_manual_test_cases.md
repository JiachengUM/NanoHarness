# Duplex + v2 手动测试用例

这份清单用于验证当前 POC 是否同时保留了两类能力：

- Duplex 侧：连续听音、判停、短附和、停播、实质性插话、回声抑制。
- v2 侧：异步提交、结果回灌、多任务并行、定向取消、任务修改、过期结果抑制。

这里不把 Duplex 的黑盒声学能力当成既定事实。涉及判停、抗干扰和非面向助手语音的用例，目标是记录实际表现，而不是预设一定通过。

## 测试范围

当前适合测试的异步工具：

- 地点搜索
- QQ 音乐单曲、歌单、专辑搜索
- Web 搜索

当前不作为通过项：

- 天气：工具当前未注册。
- 音乐播放：媒体执行工具当前未注册，只测试搜索结果。
- 真正取消正在生成的 v2 模型轮次：目前实质性插话会立即停播旧语音，但新请求仍可能等待当前 `agent.astream` 结束。

## 测试前准备

1. 启动 Duplex 版后端和现有 v2 前端。
2. 确认页面显示语音链路已连接，并进入连续监听状态。
3. 使用外放扬声器，不戴耳机，以便同时验证浏览器 AEC 和自回声。
4. 每轮测试前等待上一轮语音和任务结束；取消类用例除外。
5. 观察三个位置：页面对话、右侧任务/运行时面板、后端终端。

每个用例至少记录：

| 字段 | 记录内容 |
| --- | --- |
| ASR | 最终转写是否完整，是否出现重复或回声转写 |
| 首次反馈 | 是否快速给出“正在查询”类占位确认 |
| 打断 | 旧语音是否立即停止，是否稍后又恢复 |
| 任务 | 创建、运行、成功、取消是否符合预期 |
| 回灌 | 真实结果是否只播报一次，取消后是否仍回灌 |
| 泄漏 | 终端是否出现 `[DUPLEX NATIVE LEAK]` |

## P0：基础链路

### P0-01 连续免按键的两轮对话

话术：

1. “帮我找静安寺附近适合安静聊天的咖啡店。”
2. 第一轮完全结束后直接说：“再帮我找一家人均低一点的。”

通过标准：

- 两轮都无需按键或重新开麦。
- 第二轮转写和回答能利用第一轮上下文。
- 每轮只创建一次对应业务任务。
- Duplex 自带回复、音频或 function call 不进入用户可见对话。

失败信号：

- 第一轮结束后麦克风不再监听。
- 第二轮被当成无上下文的新问题。
- 出现 v2 和 Duplex 两份回答。

### P0-02 异步占位回执和真实结果

话术：

“帮我搜索一下最近关于端到端语音模型的三条重要进展，查到后简要告诉我。”

通过标准：

- 工具提交后先收到一个简短的“正在查询”类反馈。
- 占位反馈不编造搜索结果。
- 真实结果稍后回灌，并由语音播放。
- 同一个真实结果不重复播报。

失败信号：

- 必须等待搜索完成才有任何反馈。
- 把占位回执当成真实结果。
- 页面有结果但没有 TTS，或同一结果播放多次。

### P0-03 短附和不触发 v2

操作：

1. 发起一个会产生两三句话回复的查询。
2. 在助手播报时分别说一次“嗯”和“好的”。

通过标准：

- 播放可以短暂 duck，随后继续。
- “嗯”或“好的”不会创建用户业务轮次或新任务。
- 原回复不会从头重播。

失败信号：

- 短附和被提交给 v2。
- 原语音被永久停止。
- 产生“有什么可以帮你”之类的新回答。

### P0-04 明确停播

操作：

1. 发起一个有较长结果的查询。
2. 播报中说：“先别念了。”

通过标准：

- 当前 TTS 立即停止。
- 不创建新的业务任务。
- 已完成的文本和任务结果仍保留在页面。
- 后续可以直接说下一条请求，麦克风仍可用。

失败信号：

- 停播明显延迟，或停掉后又恢复播放。
- “先别念了”被发送给 v2。
- WebSocket 或监听会话被一起关闭。

### P0-05 实质性插话

操作：

1. 说：“帮我找静安寺附近评分高的咖啡店。”
2. 助手播报时插话：“换一个方向，帮我找陆家嘴附近适合带电脑办公的咖啡店。”

通过标准：

- 旧语音立即停止。
- 第二句话完整进入 v2，而不是只执行停播。
- 新地点和新条件形成新请求。
- 旧语音不会在新回复之后重新出现。

当前限制：

- 这验证的是“立即停播 + 新请求可进入队列”，不代表当前 v2 模型生成已经被硬取消。

## P1：Duplex 黑盒能力观测

### P1-01 犹豫和长停顿判停

话术：

“帮我找一下……（停 1 至 2 秒）静安寺附近……（停 1 秒）适合聊天的咖啡店。”

通过标准：

- 最终只提交一个完整请求。
- 停顿期间不会提前触发两个残缺任务。
- 最终转写包含核心地点和条件。

记录：

- 分别测试 0.5 秒、1 秒、2 秒停顿，记录开始被错误截断的阈值。

### P1-02 同一句中的自我更正

话术：

“帮我找陆家嘴附近的咖啡店，不对，改成静安寺附近，要安静一点的。”

通过标准：

- 最终只创建一个地点搜索任务。
- 搜索条件以静安寺和安静为准。
- 不应先创建陆家嘴任务再取消。

### P1-03 外放自回声

操作：

1. 让助手播报一段至少 10 秒的结果。
2. 全程不要说话。
3. 分别用低、中、高三个扬声器音量测试。

通过标准：

- 助手自己的声音不形成有效用户转写。
- 不发生无缘无故的 duck、停播或新任务。

记录：

- 每个音量下的误转写次数、误打断次数和是否出现 Duplex 原生回复。

### P1-04 旁人说话和非面向助手语音

操作：

1. 助手播报时，让旁人从侧面说：“晚上吃什么，要不要点外卖？”
2. 再让旁人从正面以正常音量重复一次。

观察目标：

- 记录 Duplex 是否能区分旁人/非面向助手语音。
- 如果产生最终转写，当前桥接层会把绝大多数非空文本提交给 v2，因此很可能误触发新轮次。

失败信号：

- 旁人语音稳定触发 v2，说明 POC 尚不能依赖 Duplex 自动完成“是否在对 AI 说话”的过滤。

### P1-05 Duplex 原生输出隔离

操作：

连续完成 5 个普通语音请求，其中至少包含一个地点搜索和一个 Web 搜索。

通过标准：

- 页面和扬声器只出现 v2 生成的回复。
- 后端终端不出现 `[DUPLEX NATIVE LEAK]`。
- 不出现 Duplex 自己发起的 function call。

## P1：v2 异步长任务

### P1-06 两个任务并行、分批回灌

话术：

“同时帮我找静安寺附近适合聊天的咖啡店，再搜索一下上海这个周末值得看的展览。”

通过标准：

- 两个独立工具任务都被提交。
- 占位确认合并成一个自然短句，不逐个念内部工具信息。
- 两个结果可按实际完成顺序分批回灌。
- 后到的结果不会重复前一个结果。

### P1-07 pending 期间处理无关新需求

操作：

1. 发起：“搜索一下最近端到端语音交互模型的重要进展。”
2. 在任务仍显示运行中时说：“顺便推荐一张适合开车听的周杰伦专辑。”

通过标准：

- Web 搜索继续运行。
- 新的音乐搜索独立提交。
- 两个结果分别回灌，不互相覆盖。

### P1-08 定向取消一个任务

操作：

1. 先执行 P1-06，确认两个任务都仍在运行。
2. 说：“取消查展览的任务，咖啡店继续查。”

通过标准：

- 只取消 Web 搜索，地点搜索继续。
- 收到简短取消确认。
- 已取消任务的迟到结果不进入对话，也不播放。

失败信号：

- 两个任务都被取消。
- 取消了错误任务。
- 终端显示取消成功，但展览结果随后仍被回灌或播报。

### P1-09 多任务下的模糊取消

操作：

1. 保持两个任务同时运行。
2. 说：“取消那个任务。”

通过标准：

- 助手询问要取消哪一个。
- 在用户澄清前不应批量取消。

### P1-10 修改正在执行的任务

操作：

1. 说：“帮我找静安寺附近适合聊天的咖啡店。”
2. 在任务仍运行时说：“改成陆家嘴附近，其他条件不变。”

通过标准：

- 旧任务先被取消。
- 收到取消 observation 后，再用“陆家嘴 + 适合聊天”的完整条件提交新任务。
- 不能让新旧两个任务长期同时存在。
- 静安寺任务即使迟到成功，也不应回灌或播报。

### P1-11 单任务取消和重复取消

操作：

1. 发起一个 Web 搜索。
2. 任务运行中说：“不用查了，取消这个搜索。”
3. 收到确认后再说：“再取消一次刚才的搜索。”

通过标准：

- 第一次取消当前唯一的活跃任务。
- 第二次返回无需取消或无操作，不报错。
- 不产生迟到结果播报。

### P1-12 没有活跃任务时取消

话术：

“取消刚才的搜索。”

前提：

- 当前没有 pending 或 running 任务。

通过标准：

- 不调用取消工具，或自然说明当前没有可取消任务。
- 不因历史对话里曾出现搜索就错误取消已结束任务。

## P2：交叉压力测试

### P2-01 停播不等于取消任务

操作：

1. 发起一个 Web 搜索。
2. 在“正在查询”类反馈播放时说：“先别念了。”
3. 保持等待，不再发新指令。

通过标准：

- 只停止当前 TTS。
- 后台异步任务继续。
- 真实结果完成后仍能进入页面；是否自动播报需要记录当前产品选择。

这个用例用于确认播放生命周期和任务生命周期没有被错误绑定。

### P2-02 先停播，再定向取消

操作：

1. 同时发起地点和 Web 搜索。
2. 播报中先单独说：“先别念了。”
3. 等停播完成后再说：“取消查展览的任务，咖啡店继续。”

通过标准：

- 第一步只停播。
- 第二步才进入 v2 并取消指定任务。
- 地点搜索保持运行并正常回灌。

### P2-03 “停播 + 业务命令”同句探针

话术：

“先别念了，取消查展览的任务，咖啡店继续。”

当前预期：

- 现有确定性路由只要命中“先别念了”，整句话就按停播处理，后半句不会进入 v2。

用途：

- 这是已知边界探针，不计入 POC 通过率。
- 若演示需要复合指令，必须拆成 P2-02 的两个语音轮次。

### P2-04 任务结果到达时用户正在说话

操作：

1. 发起一个异步搜索。
2. 在预估结果即将回灌时持续说一段 5 至 10 秒的新问题。

通过标准：

- 新用户语音不被任务结果 TTS 覆盖。
- 页面仍保留异步结果。
- 用户说完后不会混播两条音频。

记录：

- 结果是延后播报、仅显示不播报，还是被丢弃；三者需选定一种产品语义。

### P2-05 快速连续三轮

话术间隔约 300 至 500 毫秒：

1. “找静安寺附近的咖啡店。”
2. “要安静一点。”
3. “不对，改成陆家嘴。”

观察目标：

- Duplex 如何切分三个音频意图。
- v2 是否把后两轮识别为任务修改。
- 最终只保留一个正确目标，且旧结果不回灌。

这是压力用例，不建议作为首次演示的主路径。

## 建议执行顺序

首次演示前只跑以下 8 个主用例：

1. P0-01 连续两轮
2. P0-02 占位回执和真实结果
3. P0-03 短附和
4. P0-04 明确停播
5. P0-05 实质性插话
6. P1-06 两任务并行
7. P1-08 定向取消
8. P1-10 修改任务

然后再跑 Duplex 黑盒能力和 P2 压力用例。这样可以把“业务链路是否正确”和“声学交互上限如何”分开判断。
