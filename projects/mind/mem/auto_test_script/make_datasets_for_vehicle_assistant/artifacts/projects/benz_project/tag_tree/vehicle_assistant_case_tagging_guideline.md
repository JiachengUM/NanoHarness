# 奔驰项目车机助手评测集 Case 打标指南

## 1. 文件与对齐关系

- 标签树文件：`vehicle_assistant_case_tag_tree.json`
- 标签树结构：对齐 `auto_tagger/tag_tree_schema.py` 的 `TagTree` / `TagTreeNode` 格式
- Case 数据格式：对齐 `case_schema.py`，最终写入 `TestCase.tags: list[str]`

## 2. 使用原则（强约束）

- 只允许选择**叶子标签**写入 `tags`
- 每个 case 建议至少包含 3 类标签：产品功能标签 + 通用对话能力标签 + 结构/难度标签
- 涉及风险或合规问题时，补充 `安全与合规` 标签
- `评测结果预期` 为可选统计标签
- **本项目聚焦奔驰车机助手核心冒烟能力**：覆盖通信、车控、导航、媒体、记忆、S2S 闲聊、联网信息查询、定时任务等模块

## 2.1 项目特有写作原则（覆盖基础原则）

### 2.1.1 来源与素材

- 用例素材来源于奔驰核心冒烟测试集 CSV，按 base 标签树能力点逐条转化
- CSV 中 "7/23 测试结果" "7/27 测试结果" 列仅作为转化参考，不写入 case；nl_assertion 一律按**理想助手预期**编写
- CSV 中标注为「复杂」「【复杂】」的 case，需要按 `约束组合` / `多轮任务_2到3轮` / `长链路任务_2到3步` 等难度标签强化覆盖

### 2.1.2 通信操作能力域（base 新增）

base 标签树原不含通信模块，本项目新增以下叶子：
- `按号码拨打`：按用户口述号码直接拨打车载电话
- `按联系人拨打`：按联系人姓名拨打车载电话
- `按客服拨打`：按品牌客服、服务热线等名称拨打车载电话
- `蓝牙开关`：打开或关闭车载蓝牙
- `蓝牙连接控制`：主动连接或断开已配对手机蓝牙
- `手机互联开关`：打开或退出 CarPlay/HiCar 等手机互联功能

### 2.1.3 S2S 闲聊与拟人能力域（base 新增）

CSV 中 S2S 模块覆盖以下叶子，写作时 case_id 与 nl_assertion 须突出对应能力：
- `情绪安抚` / `故事笑话讲述` / `方言交流` / `语气切换` / `哼唱表演` / `自我介绍` / `话题闲聊`

### 2.1.4 联网信息查询主题（base 新增子模块）

CSV 中 onlineService / 卡片类 / 大模型 等模块涉及多种联网查询主题，新增以下叶子便于细粒度打标：
- `天气查询` / `新闻资讯查询` / `票务信息查询` / `财经股市查询` / `通用知识查询`

### 2.1.5 系统功能操作 / 车控查询 / 定时任务（base 新增）

- `系统功能操作`：应用商店操作、应用启动、语音助手退出、唤醒词响应、拍照功能、车况查询
- `车控查询`：胎压查询、当前位置查询、车外温度查询
- `定时任务`：提醒设置

### 2.1.6 奔驰项目特有写作要点

- **真实地址**：对话内容会被语音读出，导航/POI 用例必须使用真实地址，禁止 'XX路' 等占位路名（CSV 中 `我要去XXX`、`其他城市的某个POI` 这类占位写法需替换为真实地点）
- **结果预期不剧透**：用户台词不直接说出判断标准
- **多轮拆分**：CSV 中明显多轮的复杂场景（如"复杂车控 - 衣服湿透了给我吹吹"对应的多轮纠错）需补成 2~3 轮 expected_script
- **车辆能力边界**：CSV 中 7/27 测试结果显示部分功能奔驰车机不支持（HUD、座椅加热、方向盘加热、氛围灯律动等），nl_assertion 仍按理想助手预期编写（评测应做对，不是实际做错）
- **CSV 测试备注不写入**：CSV 中 "测试结果" "备注" 等列是测试人员人工填写的内容（如"反馈不支持""偶发""TTS卡顿"等），转化 case 时一律忽略，nl_assertion 只按理想助手预期编写

### 2.1.6b 定时任务叶子说明（第七批扩展）

第七批定时任务 case 按时间规律类记忆 case 处理，新增叶子：

| 叶子 | 说明 | case 范围 |
|---|---|---|
| `提醒设置` | 按用户指定时间设置提醒 | leaf-benz-194/195 |
| `定时提醒触发` | 到时主动触发提醒，无需用户再次询问 | leaf-benz-194/195 |

**定时任务作为时间规律类记忆 case 的处理原则**：
- **多次会话结构**：第一次会话用户设置提醒，第二次会话（car_info 时间推进到提醒时刻）助手主动触发提醒
- **car_info 时间推进**：第一次会话 car_info 时间为设置时刻，第二次会话 car_info 时间推进到提醒时刻
- **用户台词不泄题**：第二次会话用户台词为"（静默等待）"，不主动询问提醒，由助手主动触发
- **助手主动触发**：第二次会话助手须在到达提醒时刻时主动触发提醒，不等用户询问
- **nl_assertion 要求**：第一次会话须确认设置（含具体提醒时间），第二次会话须主动触发（含具体事项），不得仅回复"时间到了"

### 2.1.7 重试先导段（奔驰项目特有，强制保留）

奔驰项目所有 case 的 `expected_script` **必须**以统一的**重试先导段**开头（本条为项目级原则，覆盖通用原则§7.3.7的指引；通用原则只约束前导段的通用结构，重试先导段的具体内容由本节定义）：

```
管家可能耳背，有时听不到导致没能回复你，那么你扮演用户时如果发现管家没说话的话，你可以重试最多3次，每次重试时都需要在指令前加上固定的唤醒词"你好，你好奔驰"，且你可以把除了唤醒词之外的内容换各种同义说法重试。另外如果管家明确表示当前无法执行你的指令（比如要求车辆处于特定状态、请你自己手动操作、当前功能受限、需要先满足某些前置条件等），那就不要再反复尝试了，直接接受现状，不要继续追问或换说法重试。

用户：xxx
管家：（期望…）
...
```

先导段含两部分规则：
1. **重试规则**：管家耳背没回复时，假人最多重试3次，每次加唤醒词"你好，你好奔驰"，可换同义说法
2. **能力受限不纠缠规则**：管家明确表示当前无法执行（如要求车辆特定状态、请用户手动操作、功能受限、需满足前置条件等），假人不再反复尝试，直接接受现状

**与通用应变规则的关系**：重试先导段之后紧接通用原则§7.3.8定义的两条演员应变规则（「盲选第一个」+「简洁回复承接」，标准文案见通用写作原则§7.3.8），用空行分隔。完整前导 = 重试先导段 + 盲选规则 + 简洁承接规则。

**强制规则**：
- **审核时不得把重试先导段误判为格式错误**：先导段是合法的人设/规则前导段（通用原则§7.3），不是"非用户：/管家：格式的杂段"（审核原则§F4）
- **修复时必须原样保留重试先导段**：审核修复 LLM 不得删除、改写、压缩先导段；修复后的 `expected_script` 必须仍以该先导段开头
- **先导段位置**：必须是 `expected_script` 的第一段，与正文之间用空行分隔
- **先导段内容统一**：所有 case 使用同一份先导文案，不得 case 间不一致

**修复兜底**：修复脚本（`fix_case_by_audit.py` / `batch_audit_fix.py`）在 LLM 返回修复结果后，必须检查 `expected_script` 是否仍以重试先导段开头；若被删除，自动补回。

### 2.1.8 JSON 写作约定（引用共享原则）

本项目遵循共享写作原则 §15 JSON 写作约定与格式校验，详见 `skills/_shared_case_writing_principles.md` §15。

**核心要点**：case 字符串值内部不得使用 ASCII 双引号 `"`，引用中文内容用中文引号 `"..."` 或单引号 `'...'`。每写完一批必跑 `check_json_format.py` 校验。

## 6. 命名与维护规范

- 标签名优先短中文短语，避免英文工具名
- 叶子标签必须可测试、可断言，避免抽象词
- 产品视角只放用户可感知能力；通用能力放 Agent 视角
- 改名或合并标签时记录映射，避免历史数据失配
