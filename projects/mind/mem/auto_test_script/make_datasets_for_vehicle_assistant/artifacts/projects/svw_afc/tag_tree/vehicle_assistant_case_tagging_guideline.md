# 上汽大众（SVW）车机助手评测集 Case 打标指南

## 1. 文件与对齐关系

- 标签树文件：`vehicle_assistant_case_tag_tree.json`
- 标签树结构：对齐 `auto_tagger/tag_tree_schema.py` 的 `TagTree` / `TagTreeNode` 格式
- Case 数据格式：对齐 `case_schema.py`，最终写入 `TestCase.tags: list[str]`
- **本项目不区分车型**：所有用例均按上汽大众（SVW）通用车机助手口径编写，标签树不设车型维度。

## 2. 使用原则（强约束）

- 只允许选择**叶子标签**写入 `tags`
- 每个 case 建议至少包含 3 类标签：产品功能标签 + 通用对话能力标签 + 结构/难度标签
- 涉及风险或合规问题时，补充 `安全与合规` 标签
- `评测结果预期` 为可选统计标签

## 2.1 项目特有写作原则（覆盖基础原则）

本项目标签树 = 基础标签树（车控/导航/联网/媒体/记忆等通用能力域）+ 三份 PRD 引入的项目增量。写作时须与项目特有子树口径对齐：

### 2.1.1 POI 搜索推荐（PRD_POI推荐_V0.3）

- **四类边界**：大模型 POI 搜索仅覆盖 **美食 / 景点 / 休闲娱乐 / 住宿** 四类；四类之外的 POI 归 SDS（语音交互系统）处理，不作为大模型 POI 用例。
- **细分品类**：四类之下有细分品类（地方菜/火锅/5A 景点/温泉馆/KTV/高档型酒店/民宿等），打标用 `细分品类识别`。
- **搜索标签**：服务设施/门店特色/权威口碑等标签（包厢/停车/Wi-Fi/可预约/5A/五星级等），打标用 `搜索标签筛选`。
- **降级逻辑**：无结果时扩大范围 5→10→15km，再降标签权重，再联网搜索；`无结果` 类用例按该链路设计预期。
- **多轮上限**：最多 5 轮滚动上下文内补充筛选或对列表二次排序。
- **播报规则**：结果超过 3 个仅播报排序前 3（TTS 播报，NLG 文本不展示）；打标用 `结果播报前3`。
- **可见即可说**：语音点击屏幕元素（第 N 个/导航到第 N 个/播放/个人中心/返回等），打标用 `可见即可说`。
- **导航拉起**：经「地址 + 名称」打开本地地图 APP 对 POI 发起导航，打标用 `POI导航拉起`。
- **行驶安全**：行驶中禁止中控屏播放，须二次确认/toast；相关用例打标 `行驶安全限制`，并注意与通用 `安全与合规` 组合。

### 2.1.2 大模型基础能力（PRD_大模型基础能力_V2.0_251219）

- **语义拒识**：非人机指向（对人说话/导航播报/杂音）、非通顺对话、与上文无关 Query、异常 CASE（极短时间多轮/多语言切换）等，均应拒识处理，打标 `语义拒识` 子树。
- **意图识别**：主意图（执行/查询/搜索类）+ 自定义意图（行程助手/儿童陪伴助手等）+ 最多 5 轮滚动上下文的意图延续理解。
- **隐式车控**：感受表达映射车控（温度/空气质量/明暗/氛围/舒适度/开车安全），如「前面路看不清→近光灯」，打标 `隐式车控` 子树对应叶子。
- **内容重新生成**：对回答不满意时自然语言触发重新生成，规避上一轮问题。
- **Hints 引导词**：回复后生成与 Query 强相关、适合语音输入的引导词，且不重复前 4 轮 QA。
- **多模态输入**：支持文本/语音/图片三种输入，图片用于相关问答（如「前方那辆车是什么牌子」）。
- **大模型内容标识**：大模型生成内容加「【AI生成】」等标识，与传统固定回复区分。

### 2.1.3 闲聊与百科（PRD_闲聊百科_V1.0）

- **闲聊**：人设一致性、回复对应性、回复正向性三维度打标。
- **百科问答**：通识知识/计算/编程/逻辑推理/英文处理/语义理解与抽取，按子树叶子打标。
- **品牌舆情处理（车厂定制）**：涉及品牌形象的负向舆情（客观事实/车主负面/管理人事负面/品牌负面）与正向推荐（推荐类/对比类/评价类），打标 `品牌舆情处理` 子树对应叶子。
  - 推荐类：优先推荐当前品牌；用户明确其他品牌则推荐对应品牌。
  - 对比类：优先当前品牌但不拉踩；对比当前品牌多车型时客观、不拉踩。
  - 评价类：对品牌/车型评价给予适宜的正向或中性回应。

### 2.1.4 项目新增能力域（意图清单 32 类）

三份 PRD 在基础树之外新增以下能力域，均已落为标签树子树，写作时按对应叶子打标：

### 2.1.5 项目写作要点

- **不区分车型**：用户台词、car_info 均不绑定具体车型配置；涉及车控时按通用上汽大众车机助手能力口径编写。
- **行驶安全前置**：涉及中控播放、导航操作等高风险场景，按 `行驶安全限制` + 通用 `高风险先确认` / `执行前确认` 组合打标。
- **品牌敏感**：涉及大众品牌形象的用例，优先走 `品牌舆情处理` 子树标签；负向舆情类必须体现「不编造、不传播、稳键表述」。
- 其余共享写作惯例见仓库共享原则 `skills/_shared_case_writing_principles.md`（含 §15 JSON 写作约定：case 字符串内部不得使用 ASCII 双引号）。

## 3. 全量标签说明

详见标签树文件 `vehicle_assistant_case_tag_tree.json`。本项目当前共 269 个叶子标签（节点总数 364），所有叶子均可直接写入 `TestCase.tags`。

## 4. 命名与维护规范

- 标签名优先短中文短语，避免英文工具名。
- 叶子标签必须可测试、可断言，避免抽象词。
- 产品视角只放用户可感知能力；通用能力放 Agent 视角。
- 改名或合并标签时记录映射，避免历史数据失配；标签树、本指南、用例库三者变更须同步。
