# benz_project 审核原则补充

本文档用于覆盖 `_shared_case_audit_principles.md` 中的基础审核原则，优先级更高。

## 项目特有审核要点

### 1. 真实地址与可读性

- 导航、POI 搜索类用例必须使用真实地址，禁止 `XX路` / `XXX商场` 等占位
- 用户台词须口语自然，避免书面化长句

### 2. CSV 转化一致性

- 转化自 CSV 的 case，user_query_lists[0][0].content 必须保留 CSV Query 列的核心语义（可微调口语化）
- CSV 中 "测试结果" 列显示未通过的 case，nl_assertion 仍按理想助手预期编写

### 3. 通信/S2S/系统功能模块

- 这些是本项目新增模块，审核时关注标签是否准确（如 `按联系人拨打` vs `按号码拨打` 不可混用）
- S2S 闲聊类 case 须有 case 专属断言（如哼唱类须断言哼唱内容，方言类须断言方言使用）

### 4. 多轮场景拆分

- CSV 中明显多轮的复杂场景（复杂车控纠错、跨域多指令）须按 expected_script 多轮格式编写
- 单轮 case 不得为冲覆盖而强行打 `多轮对话` 标签

### 5. 奔驰车辆能力边界

- CSV 中部分功能奔驰车机不支持（HUD、座椅加热、方向盘加热、氛围灯律动等）
- 这些 case 仍按理想助手预期编写 nl_assertion，不写入"功能不支持"类预期
- 若 case 主任务本身就是测"功能不支持时的兜底"（如应降级处理），须明确打 `应降级处理` 标签

### 6. 重试先导段（奔驰项目特有，审核/修复不得删除）

本项目所有 case 的 `expected_script` **必须**以统一的重试先导段开头（以"管家可能耳背"开头、含唤醒词"你好，你好奔驰"，完整文案见奔驰项目写作原则 §2.1.7）。这是通用审核原则§F4所指的**项目特有先导段**在本项目的具体落地。

**审核不得报错**：审核时不得把重试先导段误判为"格式错误""非用户：/管家：格式的杂段""多余说明"。先导段是 `expected_script` 的合法组成部分。

**修复必须保留**：审核修复 LLM 修复 case 时，必须原样保留重试先导段，不得删除、改写、压缩。修复后的 `expected_script` 必须仍以该先导段开头，先导段后用空行分隔正文。

**审核判据**：
- 若 case 的 `expected_script` 以重试先导段开头，审核**不得**因此报 F1/F2/F3 类问题。只有当先导段之后正文出现 F1/F2/F3 问题时才报
- 若 case 的 `expected_script` **缺少**重试先导段（不以"管家可能耳背"开头），判不通过，issue 的 principle 填「重试先导段缺失（项目级§6）」，dimension 填「前导段缺失」，severity 填「error必须修复」，suggestion 给出补回先导段后的完整 expected_script 开头

**修复兜底**：修复脚本在 LLM 返回修复结果后必须检查先导段是否仍在（`_ensure_preamble` / `_apply_preamble_safeguard`）；每次跑完审核修复，用 grep 检查最终产物中"管家可能耳背"出现次数 = case 数。
