# 车机助手评测集 Case 打标标签树说明（华为 HMS 自定义意图）

## 1. 文件与对齐关系

- 标签树文件：`vehicle_assistant_case_tag_tree.json`（本指南唯一事实来源，位于 `artifacts/projects/huawei/tag_tree/`）
- 标签树结构：对齐 `auto_tagger/tag_tree_schema.py` 的 `TagTree` / `TagTreeNode` 格式
- Case 数据格式：对齐 `case_schema.py`，最终写入 `TestCase.tags: list[str]`

## 2. 使用原则（强约束）

- 只允许选择**叶子标签**写入 `tags`。
- 每个 case 建议至少包含 3 类标签：产品功能标签 + 通用对话能力标签 + 结构难度标签。
- 涉及风险或合规问题时，补充 `安全与合规` 标签。
- `评测结果预期` 为可选统计标签。
- **合成集覆盖（composite）**：以本标签树全部叶子为全集，在 `vehicle_assistant_leaf_cases.json` 中 **`id`** **以** **`composite-`** **开头的 case** 要求**每个叶子至少对应 ≥8 条 case**（某叶的「关联 case 数」= 含该叶于 `tags` 的 case 个数）；合成集体量规划约 **1200** 条。缺口统计：`datasets/report_composite_leaf_tag_coverage.py --min 8`（脚本只统计 `composite-*` 子集）。
- **本树增量范围**：本树在基础标签树之上补入了华为传统垂域二级意图、中枢落域与仲裁、搜索/出行/用车/趣味四助手域、说法改写等增量。

## 2.1 车载助手感知边界（评测口径）

编写 **`nl_assertion`** **/** **`expected_script`** **/ 用户台词 /** **`car_info`** 时，须与本评测集的隐含前提一致；叶子标签树刻画的是产品视角下**可评测**的能力域（车控、导航与检索、记忆与对话策略等），**未在标签树中单独落成工具的感知通道，不要默认助手具备**。

- **默认不具备「车载视觉」语义**：不把「实时看懂环视/倒车影像画面、替你目测旁车间距/够不够剐蹭、凭画面判断泊位线」等当作可被评测的助手能力。**高风险场景尤其禁止**把结论建立在助手「看一眼外部环境」之上；应变更为 **风险提示 + 保守操作流程 + 承认不确定性 + 引导乘员目视确认**。
- **允许的信息来源**：与标签一致的 **互联网检索**（天气、POI、营业时间等）、导航/路况类 **结构化或文本摘要**，以及 **`car_info`** **/ 车况里已经写明**的字段（用户口述场景锚点可写在 `car_info`，不要指望助手从无文本通道「看见」）。
- **车况摘要 vs 实时画面**：若仅注入「倒车影像：画面模糊提示」这类**文本摘要**，评测期望是助手据此做 **策略与安全建议**，**不得**编造画面细节或假装读过影像帧。若题目需要 **雷达/障碍物枚举或有无判定**，须在 **同会话** **`car_info`** **注入可引用的结构化摘要**；否则断言应要求助手 **承认未注入、不得口述伪造扫描结果**，并引导目视。
- **示例口吻**：口语短句、略带着急或埋怨均可；避免让用户像在念评测任务书（过长从句、破折号串联多条判定点）。其它撰写惯例见仓库 skill「vehicle-assistant-composite-cases」之 **`user_query_list`** **口语规范**。
- **与其它文档对齐**：合成 JSON 撰写惯例见仓库 skill「vehicle-assistant-composite-cases」中的同标题小节。

## 3. 全量标签说明（每个标签均含名称/详情/例子）

> 本树在基础标签树之上做华为 HMS 自定义意图项目的增量调整。叶子标签可直接用于打标。
> 例子统一采用真实车主说法句式：`用户说…，期待助手…`。

- `车机助手评测标签树`
  - 详情：用于理想化车机助手评测集的case打标，叶子节点可直接写入TestCase.tags
  - 例子：用户说“我这会儿有个用车需求”，期待助手先理解目标，再给出可执行结果。
  - `产品视角标签子树`
    - 详情：按具体业务功能分层：能力域 -> 功能模块 -> 可直接打标的评测点
    - 例子：用户说“我这会儿有个用车需求”，期待助手先理解目标，再给出可执行结果。
    - `中枢落域与意图路由`
      - 详情：华为HMS中枢的落域判定与跨域仲裁能力
      - 例子：用户话术涉及多个能力域，期待助手先判定落在哪个域再正确响应。
      - `五域落域`
        - 详情：将用户意图路由到五域或大模型
        - 例子：用户一句话可能落入多个域，期待助手正确路由到五域或大模型。
        - `传统垂域落域`
          - 详情：高频车载能力（车控/导航/媒体/电话/系统设置等）正确落入传统垂域
          - 例子：用户说“打开空调”，期待助手落入传统车控垂域直接执行。
        - `大模型落域`
          - 详情：「用大模型」类发话一律走大模型处理
          - 例子：用户说“用大模型帮我写一段路书”，期待助手走大模型处理该请求。
      - `出行与导航仲裁`
        - 详情：出行助手与导航传统垂域的仲裁优先级
        - 例子：用户说出行与导航相关意图，期待助手按仲裁优先级别分到导航垂类或出行助手。
        - `明确导航意图优先`
          - 详情：「导航去xx」「到xx的路线」「我想去xx」「去xx」等明确导航意图落导航垂类（第一优先级）
          - 例子：用户说“导航去北京天安门”，期待助手落导航垂类直接规划路线。
        - `指定地点落导航`
          - 详情：指定具体POI/品牌词/省市区，或固定地点类型（充电桩/加油站/停车场/卫生间/金融保险/公共设施/交通运输仓储）落导航垂类（第二优先级）
          - 例子：用户说“搜索国贸附近的加油站”，期待助手落导航垂类检索固定地点类型。
        - `泛化地点推荐落出行`
          - 详情：其他地点推荐（湘菜馆/咖啡店/景点/美食等）、含限定条件或模糊泛化地点搜索落出行助手
          - 例子：用户说“国贸附近有啥好吃的”，期待助手落出行助手做地点推荐。
        - `隐晦需求落出行`
          - 详情：隐晦需求表达（我饿了/想给小孩过生日/我想出去玩）落出行助手
          - 例子：用户说“我饿了”，期待助手落出行助手推荐吃饭的地方。
        - `导航去推荐地转导航`
          - 详情：「导航去XXX（POI/品牌词）」统一由导航垂类响应，即使POI来自出行推荐结果
          - 例子：用户看完地点推荐后说“就第二家，导航过去”，期待助手转导航垂类发起导航。
        - `推荐理由询问落出行`
          - 详情：询问推荐理由/特色/对比由出行助手大模型总结
          - 例子：用户说“为什么推荐这家”，期待助手落出行助手总结推荐理由。
        - `长途兜底落出行大模型`
          - 详情：长途旅游规划/路线推荐由出行助手大模型兜底
          - 例子：用户说“帮我做个云南七日游路线规划”，期待助手落出行助手大模型兜底。
      - `多轮跨域落域`
        - 详情：跨域多轮语料的落域判定
        - 例子：用户跨轮改变领域，期待助手正确判定意图域延续还是跨域。
        - `意图域延续`
          - 详情：弱多轮下意图域不变，不跨域延续原领域
          - 例子：用户问“明天天气怎么样”，接着“那后天呢”，期待助手延续在天气查询域不跨域。
        - `意图跨域转移`
          - 详情：弱多轮下显式转移领域，正确判定跨域
          - 例子：用户先“调高音量”，再说“继续调高导航音量”，期待助手识别跨域到导航域。
    - `出行助手`
      - 详情：地点推荐、行程规划与推荐交互能力
      - 例子：用户要推荐地点或规划行程，期待助手按出行规则回复。
      - `泛化地点推荐`
        - 详情：按美食/景点/咖啡店等泛化类型推荐地点
        - 例子：用户说“附近有哪些景点可以逛”，期待助手按泛化类型推荐景点。
      - `限定条件地点推荐`
        - 详情：含限定条件（价格/评分/距离/停车等）的地点推荐
        - 例子：用户说“国贸附近有便宜点的酒店吗”，期待助手按价格等条件推荐。
      - `隐晦需求地点推荐`
        - 详情：隐晦需求（我饿了/想给小孩过生日）推荐地点
        - 例子：用户说“想给小孩过生日，推荐几个地方”，期待助手推荐适合过生日的地点。
      - `推荐理由阐述`
        - 详情：阐述推荐理由/特色/对比
        - 例子：用户说“这两家哪个更适合带孩子”，期待助手对比并阐述推荐理由。
      - `长途行程规划`
        - 详情：长途旅游规划与路线推荐兜底
        - 例子：用户说“帮我规划一个江浙三日游”，期待助手给出长途行程规划。
    - `搜索助手`
      - 详情：新闻、百科、长尾小技能相关意图与仲裁
      - 例子：用户提新闻、百科或长尾技能请求，期待助手按搜索助手规则路由作答。
      - `新闻问答`
        - 详情：新闻相关意图与仲裁（喜马拉雅→传统垂域，其他→大模型新闻助手）
        - 例子：用户提新闻相关请求，期待助手先判定音源再路由。
        - `按音源点播新闻`
          - 详情：指定喜马拉雅听新闻落传统垂域
          - 例子：用户说“我想在喜马拉雅上收听最新的新闻节目”，期待助手落传统垂域点播新闻。
        - `新闻搜索`
          - 详情：按热点/关键词/类别/地区及组合搜索新闻
          - 例子：用户说“和我说说今天的新闻头条吧”，期待助手搜索并按热点给新闻。
        - `新闻信息问答`
          - 详情：对特定新闻事件提问
          - 例子：用户说“今天上午高架那起事故怎么回事”，期待助手针对该新闻事件作答。
        - `指定新闻播报`
          - 详情：按第N条/标题关键字/大模型选择播报新闻
          - 例子：用户说“播报第三条新闻”，期待助手按序号播报指定新闻。
        - `新闻深度解读`
          - 详情：深度解读新闻事件背景/角色/观点/时间轴/影响
          - 例子：用户说“这条新闻事件前因后果给我讲讲”，期待助手深度解读背景与影响。
      - `百科问答`
        - 详情：百科问答意图判定（句式+内容两维度）与19个意图大类
        - 例子：用户提问百科知识，期待助手先仲裁再作答。
        - `百科通用仲裁`
          - 详情：现有垂类/智能体优先于百科；出行/新闻/用车 > 大模型百科 > 闲聊
          - 例子：用户问一个既像导航又像百科的问题，期待助手优先走现有垂类再考虑百科。
        - `百科意图大类`
          - 详情：自然科学/工程技术/医学/社会科学/文化艺术/历史/体育/地理/经济/人物/书籍/影视/游戏/生活/教育/政治/宗教/法律/网络/交通等意图大类
          - 例子：用户说“吃生鱼胆真的能治病吗，会有哪些危害”，期待助手按百科意图作答。
      - `长尾小技能`
        - 详情：长尾小技能意图分类
        - 例子：用户提长尾技能请求，期待助手按对应小技能响应。
        - `笑话`
          - 详情：播放/更换笑话、绕口令
          - 例子：用户说“讲个笑话听听”，期待助手播放或讲笑话。
        - `科学计算`
          - 详情：加减乘除/连续运算/N次方根号阶乘/圆周率正弦余弦
          - 例子：用户说“13乘以245的结果是多少”，期待助手给出计算结果。
        - `单位换算`
          - 详情：面积/体积/速度/长度/重量/温度/时间/数据换算
          - 例子：用户说“100公里等于多少英里”，期待助手完成单位换算。
        - `时间查询`
          - 详情：公历/农历/时间/时区/节日/节气/假期查询
          - 例子：用户说“距离五一还有几天”，期待助手查询并回答。
        - `汇率换算`
          - 详情：货币汇率查询与换算
          - 例子：用户说“100美元能换多少人民币”，期待助手按汇率换算。
        - `翻译`
          - 详情：中英互译、指定语种
          - 例子：用户说“桌子翻译成英文”，期待助手输出英文翻译。
        - `古诗`
          - 详情：古诗对答/创作
          - 例子：用户说“背一首李白的静夜思”，期待助手背诵古诗。
        - `星座`
          - 详情：星座运势/性格/配对/物象/来源
          - 例子：用户说“金牛座今天运势怎么样”，期待助手查询星座运势。
        - `故事`
          - 详情：创作/改写故事
          - 例子：用户说“给我讲个睡前小故事”，期待助手创作或讲述故事。
    - `用车助手`
      - 详情：车机知识、车辆知识与法规保险用车知识
      - 例子：用户问用车知识，期待助手归到车书类知识作答。
      - `车机知识`
        - 详情：系统功能/导航/通话/影音/车机互联/车辆设置/空调设置/系统设置使用说明
        - 例子：用户说“怎么连接蓝牙”，期待助手讲解车机蓝牙连接用法。
      - `车辆知识`
        - 详情：车辆控制/规格/仪表/故障处理/维护保养/驾驶/安全须知/术语解释
        - 例子：用户说“仪表盘这个灯亮了是什么意思”，期待助手解释车辆仪表含义。
      - `交规保险知识`
        - 详情：违法行为处罚/车险/车牌归属地/车辆购置租赁/驾驶技巧与安全/语音操作方法
        - 例子：用户说“酒后驾车扣多少分”，期待助手回答交规处罚。
    - `趣味助手`
      - 详情：闲聊支持范围
      - 例子：用户发起闲聊，期待助手按趣味助手范围陪伴式回应。
      - `闲聊`
        - 详情：日常问候/人设询问/情感陪伴/助手状态/主观点询问/投诉抱怨/自定义角色扮演
        - 例子：用户说“我今天好累啊”，期待助手做情感陪伴式回应。
    - `说法改写`
      - 详情：传统垂域语料说法改写能力
      - 例子：用户话术口语化或多轮依赖前文，期待助手先改写成规范说法再执行。
      - `标准化改写`
        - 详情：口语化/生僻拗口/ASR噪声/同义说法规格化归一
        - 例子：用户说“空调帮我开开吧”，期待助手改写归一并执行开启空调。
      - `上下文改写`
        - 详情：指代消解/上下文继承/跨域继承/一语多意图/否定意图/模糊意图改写
        - 例子：用户先说“导航到静安寺”，再说“那附近有啥好吃的”，期待助手消解指代并继承上下文。
      - `弱关联多轮改写`
        - 详情：强多轮（依赖前文）与弱多轮（语义自洽可补充）改写
        - 例子：用户说“再来一个”，期待助手结合前文完成强多轮改写。
    - `车控操作`
      - 详情：车内设备控制能力
      - 例子：用户说“打开空调，温度调到23度”，期待助手按要求完成空调控制并反馈结果。
      - `空调操作`
        - 详情：空调相关控制
        - 例子：用户说“打开空调，温度调到23度”，期待助手按要求完成空调控制并反馈结果。
        - `空调开关`
          - 详情：可正确打开或关闭空调（含后排空调）
          - 例子：用户说“打开空调”，期待助手执行空调开关并反馈结果。
        - `温度调节`
          - 详情：可正确调高/调低/设定目标温度
          - 例子：用户说“把空调调暖和一点”，期待助手正确响应温度调整需求。
          - `温度增减调节`
            - 详情：可正确调高或调低空调温度
            - 例子：用户说“再凉两度”，期待助手小幅调节温度，勿一步跳到极冷。
          - `温度直接设定`
            - 详情：可正确设定明确目标温度（如23度）
            - 例子：用户说“空调23度”，期待助手设定到口述目标温度。
        - `温度分区调节`
          - 详情：主驾/副驾/后排/后排左右各区温度增减与直接设定
          - 例子：用户说“主驾空调温度调到26度”，期待助手精确调节主驾区域温度。
        - `风量调节`
          - 详情：可正确增减或设定风量
          - 例子：用户说“把风再大一点”，期待助手正确响应风量调整需求。

        - `对抗歧义`
          - 详情：表达模糊、冲突或含噪声干扰
          - 例子：用户说“去那个近又安静的地方”，期待助手先澄清再执行，避免误操作。
        - `长链路任务`
          - 详情：任务包含较长步骤链，且后续步骤依赖前序结果
          - 例子：用户说“先找店、再比较、再选、再导航”，期待助手按依赖顺序完成整条链路。
          - `长链路任务_2到3步`
            - 详情：任务链包含 2 到 3 个依赖步骤
            - 例子：用户说“先找店，再直接导航过去”，期待助手完成2到3步依赖链路。
          - `长链路任务_4到6步`
            - 详情：任务链包含 4 到 6 个依赖步骤
            - 例子：用户说“先搜店、再筛选、再比较、再选、再导航”，期待助手串联4到6步。
          - `长链路任务_7步及以上`
            - 详情：任务链包含 7 个及以上依赖步骤
            - 例子：用户长流程含7步以上依赖操作，期待助手全程状态一致并可恢复。
    - `评测结果预期`
      - 详情：用于评测统计分析的结果标签
      - 例子：用户说“我这会儿有个用车需求”，期待助手先理解目标，再给出可执行结果。
      - `可完成`
        - 详情：理想助手应可完成任务
        - 例子：标注期望：理想助手应能顺利完成该 case 主任务。
      - `需澄清`
        - 详情：理想助手应先澄清后继续
        - 例子：标注期望：理想助手应先澄清关键歧义再继续（如多家“万达”）。
      - `应拒绝`
        - 详情：理想助手应明确拒绝
        - 例子：标注期望：理想助手应明确拒绝不当或危险请求。
      - `应降级处理`
        - 详情：理想助手应提供可执行替代方案
        - 例子：标注期望：理想助手无法原样完成时须给可执行替代方案。

## 4. 命名与维护规范

- 标签名优先短中文短语，避免英文工具名。
- 叶子标签必须可测试、可断言，避免抽象词。
- 产品视角只放用户可感知能力；通用能力放 Agent 视角。
- 改名或合并标签时记录映射，避免历史数据失配。
